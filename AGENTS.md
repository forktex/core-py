# forktex-core Agent Guide

This repo ships **forktex-core** on PyPI: the shared ForkTex Python substrate consumed by every ForkTex service.

## Ground before you build

The rules that govern *how* to write code here are **not in this file**. They live once, in the
docs repo, and are always-inject via the `pinned` tag:

```bash
forktex knowledge search "<topic>"     # before any non-trivial change
```

| Standard | Covers |
|---|---|
| `standards/python-lint.md` | ruff/pyright gate, no `Any` in signatures, how to invoke tools |
| `standards/package-layout.md` | flat vs layered DAG, role-named layers, `__all__` as contract |
| `standards/data-access.md` | let the database do it; no SQL strings; row-value keyset |
| `standards/code-reuse.md` | consume `forktex_core`, recycle into it, what stays service-owned |
| `standards/clean-code.md` | a WHAT-comment is a missing name |
| `standards/error-envelope.md` | `{code, message, details, traceId}` and the `[api]` factory |

`docs/engineering/constraints.json` is the machine projection of those rules, each with the
check that enforces it. This file carries only what is **specific to this repo**.

## First Principles

- `forktex.json` is the project contract — **including the build gate**. The root `Makefile` is
  generated by `forktex fsd makefile sync`; a hand-edit is reverted on the next sync, silently.
  Change an atom in `forktex.json`, re-sync, then confirm a zero-diff regeneration.
- `forktex-core` is a **library** (no runtime); `make ci`, `make build`, `make publish` are the
  relevant atoms. `make start` / `stop` / `logs` are no-op placeholders.
- Canonical release gate is `make ci` (not `make acceptance`). Default branch is `master`.
- **Tests use real infrastructure.** One session-scoped Postgres 17 testcontainer shared by every
  DB-backed suite; there is no embedded or in-memory fallback, because these suites exercise JSONB
  operators, `FOR UPDATE SKIP LOCKED`, advisory locks, partial/GIN indexes, `schema_translate_map`
  and SQLSTATE codes.

## Architecture — four levels

Every module lives at a level and may import only **lower** levels + third-party. No upward
imports; no sibling-*facade* imports. L0 primitives may compose with each other (declared, with
reasons, in `tests/test_architecture/test_level_dag.py`).

| Lvl | Name | Modules |
|----:|---|---|
| 0 | primitives | `log` · `error` · `types` · `iso` |
| 1 | role facades | `database` · `cache` · `queue` · `vector` · `storage` · `store` · `vault` · `graph` |
| 2 | substrate | `grid` · `space` · `flow` |
| 3 | bootstraps | `api` · `worker` |

`catalog/` is build tooling (renders `catalog.json` → README), not a runtime module.
`catalog.json` is the machine source of truth for the levels — the DAG guard reads it, so a new
module cannot be added in one place and forgotten in the other.

A fifth level (`tech_adapters`) was investigated and **retired without being built**; anything
referencing "Level 2 role facades" or "Level 3 substrate" predates the renumber.

- `docs/ARCHITECTURE.md` — the as-is ground truth, per-package state and remaining debt
- `docs/development.md` — design principles, module checklist, how to add a module
- `docs/<module>.md` — one consumer reference per module (asserted to exist)

## Guards that run in `make ci`

`tests/test_architecture/` enforces what used to be prose. Before trusting a new guard, break
the rule once and watch it fail — that is how two false-passing guards were caught in this suite.

- level DAG (AST-parsed, incl. function-local and `TYPE_CHECKING` imports)
- cycle-debt ratchet per package (`flow` at 59 is the restructure target; `grid` and `database` at 3)
- `__all__` non-empty, resolving, and free of underscore names
- optional dependencies imported lazily, or the `ImportError` names the extra
- every package has a module docstring and a `docs/<name>.md`

`tests/test_catalog/` covers packaging and docs accuracy: every catalog extra is a real install
target, `[all]` misses nothing, and every import a doc claims actually resolves.

## Local install

```bash
poetry install --all-extras --with dev
```

Narrower extras exist for every module the catalog names — `[vault]`, `[storage]`, `[queue]`,
`[vector]`, `[store]`, `[api]`, `[worker]`, `[grid]`, `[flow]`, … or `[all]`.

## Publishing

Downstream services runtime-import this package; production resolves it from PyPI.

```bash
make ci             # full gate; must be green
make publish-test   # TestPyPI rehearsal — exercises real index resolution
make publish        # irreversible per version
```

`make ci` ends with `smoke`, which installs the **built wheel** into throwaway venvs and imports
every extra. Everything before it tests the source tree, so a packaging fault is invisible to it —
which is exactly how `[worker]` once shipped documented but undeclared.
